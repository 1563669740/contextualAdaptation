# code/ — paper reproduction code archive

**Paper**: "When Should Software Bug Fixing Be Delegated to AI? Context–Policy Matching and Adaptive Delegation for Repository-Level Software Repair"
**Underlying plan**: the implementation plan for this study (v1.0, 2026-09-14)
**Data assets**: `../experiment_root/` (216 tasks / 38 repositories / 792 sessions with frozen allocation)
**Role of this directory**: gather the reproduction code scattered across the workspace into one indexable, verifiable archive organised by paper location

---

## 0. What this archive is, in one sentence

```
experiment_root/   ← the authoritative copy (authoritative data + authoritative code). This directory never modifies it.
code/              ← archive mirror + unified launcher. Copy only, never move, never delete.
```

**Why not simply move `experiment_root/tools/` in here**: `experiment_root/audit/freeze_manifest.json`
freezes 676 artefacts with a tree digest, and `splits/randomisation.json` records the
SHA256 of the allocation generator. Moving the tool source away would directly change the
content hash of the frozen package — and that is an authoritative copy which has already
been delivered and can be verified. So what happens here is **mirroring**: 54 of the 55
files in `code/` are **byte-identical** to their source files, and the 55th has exactly one
line-level adaptation (see §4).

| Command | Effect |
|---|---|
| `python code/sync.py` | realign `code/` with `experiment_root/` (idempotent, can be rerun) |
| `python code/verify.py` | check that copies are byte-identical to their sources + full syntax check |
| `python code/run.py --list` | list every runnable script |
| `python code/run.py <script> [args]` | run any script through the unified launcher (resolves cross-module imports) |

## 3. How to run it

Every script hard-codes `ROOT = <repo root>\experiment_root` internally,
so **the copies still read and write the authoritative data**; `code/` is only an
entry point, not a sandbox. Running them writes artefacts into
`experiment_root/` — exactly the same as running directly under `experiment_root/`.

```bash
# 0) dependencies
python -m pip install -r code/requirements.txt        # PyYAML only

# 1) verify the archive (should print consistent 55 / 0 problems)
python code/verify.py

# 2) full audit (scans experiment_root only; knows nothing about code/)
python code/run.py 10_audit/audit.py

# 3) metric aggregation
python code/run.py 05_evaluation/aggregate_metrics.py

# 4) hidden evaluation (independent clean workspace)
python code/run.py 05_evaluation/evaluate.py --session-id D-S0001

# 5) pipeline self-check: recover the structure of paper Table V / Table XV from synthetic samples
python code/run.py 09_rq1_rq4_analysis/check_pipeline.py

# 6) online policy self-test (writes experiment_root/policy/extractor_self_test.json)
python code/run.py 08_rq3_policy/online_policy.py --self-test
```

### 3.1 Why `run.py` is needed

`experiment_root/tools/simulate.py` needs `import online_policy, rq2_coding`;
`admission_gate.py` / `holdout_probe.py` / `holdout_author.py` need
`import task_env, evaluate`. These scripts rely on `sys.path.insert` to find their
sibling modules, and the grouping in `code/` differs from
`experiment_root/{tools,evaluation}`.
`run.py` puts every group directory of `code/` together with
`experiment_root/{tools,evaluation,repo_cache}` onto `sys.path`, so the copies run
**without changing a single line of logic**. Verified:

```
python code/run.py 05_evaluation/admission_gate.py --help   → exit 0
python code/run.py 06_holdout/holdout_author.py status      → exit 0
python code/run.py 09_rq1_rq4_analysis/simulate.py --help    → exit 0
```

Running `python code/05_evaluation/admission_gate.py` directly also works (it uses the
absolute `ROOT`); only `holdout_author.py` must go through `run.py` — it is the only
script that derives `sys.path` from `__file__`.

## 4. The single adaptation (`path_pin`)

`experiment_root/repo_cache/fetch_repos.py` is the only file in the whole codebase that
uses `__file__` to locate its own cache directory:

```python
CACHE = os.path.dirname(os.path.abspath(__file__))
```

Once copied into `code/01_infra_noncontainer/`, `__file__` would point there, the script
would create `_inventory/` and `_snapshots/` under `code/`, and the result would diverge
from the already frozen `repo_cache/`.
So the copy changes this one line only, pinning `CACHE` to the authoritative directory:

```python
CACHE = r"<repo root>\experiment_root\repo_cache"  # code-tree adapter: pin to the authoritative cache
# note: changing this string makes code/verify.py report SOURCE_CHANGED (adaptation rule in §4);
#     after changing the path you must rerun code/sync.py to refresh the hash.
```

Not a single line of logic was changed. The adaptation rule lives in the `adapters`
section of `code_map.json`, and the exact change is recorded verbatim in the
`adaptation` field of that entry in `CODE_INDEX.json`; `verify.py` reapplies the same
rule when comparing, so this divergence can never be "forgotten". The other fetch
script `fetch_repos_tarball.py` already uses an absolute path and needs no adaptation.

## 5. This workspace is being edited concurrently

At the time of archiving (2026-09-15 08:44 +08:00), files under
`experiment_root/tools/` were still being written (`online_policy.py` 08:40,
`simulate.py` 08:39, `aggregate_metrics.py` 08:36, plus the newly appeared
`_diag_p1.py`, `_diag_p1b.py`, `_diag_freq.py`). The archive is therefore a
**snapshot of the state at that moment**:

* run `python code/verify.py` — if it reports `SOURCE_CHANGED`, there are newer edits on the source side;
* run `python code/sync.py` — realign and refresh the hashes;
* if a new, unregistered script turns up in the source directories, `sync.py` lists it
  under `unmapped` (not copied by default). To adopt it, add `--adopt-unmapped`; it then
  goes into `99_scratch/_unmapped/`, but still has to be filed manually and registered in
  `code_map.json`.

## 6. What this directory does not do

* it **does not** modify any file in `experiment_root/` — nothing is moved, nothing is deleted, nothing is renamed.
* it **does not** participate in the frozen hashes of `experiment_root`, and it is **not**
  scanned by `tools/audit.py` (the audit only walks the seven directories
  `manifests/ splits/ context_packages/ protocol/ codebook/ policy/ audit/`),
  so adding `code/` will not turn an existing audit result from PASS into WARN.
* it is **not** an archive of **data** such as `dataset/holdout_tests/*/tests_holdout_task.py` —
  that is evaluation material, not code.
* `09_rq1_rq4_analysis/simulate.py` produces **SYNTHETIC / NOT_A_RESULT** data,
  used to validate the pipeline rather than to produce conclusions; that marker must
  always be attached when citing it.
